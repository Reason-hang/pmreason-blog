## 第1层 · 业务理解力层

### 1.0 Phase 0 核心结论回顾与继承

本阶段继承 Phase 0 的五个结论：

1. **WMS是海外仓OTWB中的核心系统**：OMS承接上游单据和指令，TMS/LMS承接尾程物流，BMS承接费用与账单，但仓内实物、库位、库存、收发存作业由WMS负责。
2. **海外仓WMS的主业务链路是入库 -> 库存 -> 出库**：课程11负责入库收货上架，课程12负责基础数据和库存模型，课程13负责出库波次拣货复核称重。
3. **入库侧最有海外仓特色的是箱唛和按箱接收**：备货入库、调拨入库通常在国内先装箱、贴箱唛、打托，到海外仓后按箱识别、清点、收货。
4. **库存不是一个SKU数量**：课程反复强调SKU库存、库位库存、批次库存、库位-批次库存，以及实际库存、可用库存、锁定库存、库存流水。
5. **出库效率的核心在波次、拣货、播种、复核、称重**：B2C小件订单适合批量波次和播种式处理；B2B备货中转更偏箱/托盘和大件作业。

本阶段按用户修正处理两点：

- 课程图片、系统截图、演示截图不纳入索引，也不复刻。
- Phase 1 不做最终面试项目口径包装，只写业务事实和业务链路。

### 1.1 系统定位卡

#### 【海外仓WMS】×【跨境海外仓仓内履约场景】[地基] [高]

一句话定位：**海外仓WMS**是仓库作业团队在海外仓收货、上架、库存管理、拣货、复核、称重、发运过程中，用来把实物流、单据流和库存变化管起来的仓储管理系统。

服务对象：

| 角色 | 核心诉求 | WMS要解决的问题 |
|---|---|---|
| 仓库收货员 | 快速识别到仓货物，准确记录实收 | 通过入库单/ASN、箱唛、PDA或Web收货，避免无主货、错收、漏收 |
| 上架员 | 知道货放到哪个库位，减少乱放 | 通过上架任务、库区库位、批次/效期信息，把货从暂存区放到可追溯库位 |
| 库存管理员 | 保证系统库存和实物一致 | 通过库存查询、库存流水、盘点、调整、移库，处理账实差异 |
| 拣货员 | 按任务快速找到货，减少走动和拣错 | 通过波次、拣货任务、库位推荐、拣货容器提升效率 |
| 复核员/打包员 | 防止错发、漏发、多发 | 通过一单一件/一单多件复核、扫码校验、称重校验拦截问题 |
| 仓库主管 | 看作业进度、异常积压和人员效率 | 通过待收货、待上架、待拣货、待复核、异常处理等看板管理现场 |
| OMS/ERP/平台运营 | 看到入库、出库、库存和异常状态 | WMS把作业结果、库存变化、异常原因回写上游 |
| 财务/BMS相关人员 | 获取仓储费、操作费、物流费的业务依据 | WMS提供入库、上架、拣货、复核、称重、库存库龄等计费变量 |

核心价值：

- Before：没有WMS或WMS能力弱时，仓库靠表格、人工沟通、线下纸单和经验处理，容易出现货到了不知道归属、库存不准、错拣错发、上游不知道状态、费用缺依据。
- After：WMS把入库、库存、出库和库内作业线上化，让每一次收货、上架、锁定、拣货、复核、发运都有单据、有库存变化、有状态回写、有异常入口。

系统边界一句话：

WMS管**仓内实物和库存作业**，包括收货、质检、上架、库位库存、批次库存、波次、拣货、复核、称重、盘点、移库、库存调整；它不管平台交易、支付、营销、采购定价、承运商结算和财务总账，这些分别属于平台/ERP/OMS/TMS/BMS/财务系统。

### 1.2 业务目标

#### 1.2.1 为什么海外仓需要WMS [地基] [高]

课程9和课程10先讲了业务背景：跨境电商如果走直邮，货从中国直接发给海外消费者，链路长、时效慢；如果走海外仓，就需要提前把货批量送到海外仓，本地消费者下单后再从海外仓发货，时效可以从十几天缩短到一两天，但代价是库存风险和仓内管理复杂度上升。

因此WMS要解决的不是“有没有页面录库存”，而是四类更底层的问题：

| 业务问题 | 如果没有WMS会怎样 | WMS的业务目标 |
|---|---|---|
| 到仓识别问题 | 货到了仓库，但不知道是哪张入库单、哪个客户/货主、箱内是什么 | 通过ASN、箱唛、箱维度收货建立到仓识别能力 |
| 库存准确问题 | 系统显示有货，实物找不到；或实物在库，系统不可见 | 通过收货、上架、库位、批次、流水、盘点保证账实一致 |
| 出库效率问题 | 订单一单一单处理，拣货员反复跑货架，效率低 | 通过波次、拣货任务、播种/摘果策略提高作业效率 |
| 发货准确问题 | 拣错SKU、批次、数量，复核不严导致错发漏发 | 通过复核、称重、扫码校验和异常拦截降低错发率 |
| 上下游协同问题 | OMS/ERP不知道WMS实际收了多少、发到哪一步、库存是否变化 | 通过状态回写、库存同步、异常原因回传打通单据流 |

#### 1.2.2 WMS的核心价值 [地基] [高]

WMS的核心价值可以概括成四句话：

1. 让货物“进得来”：到仓后能识别、能清点、能收货、能处理差异。
2. 让库存“找得到”：每个SKU、批次、库位、库存状态可查询、可追溯。
3. 让订单“发得出”：出库单能分波、能拣货、能复核、能称重、能交接。
4. 让异常“兜得住”：超收、少收、货不对板、拣货缺货、复核异常、库存差异都有入口。

### 1.3 业务流程链路全景图

#### 1.3.1 海外仓端到端链路 [地基] [高]

海外仓特有的完整链路是：

```text
头程发货/国内备货处理
  -> 国内装箱、贴箱唛、打托
  -> 头程运输、报关、干线、清关、转运
  -> 海外仓到仓
  -> WMS入库收货、质检、上架
  -> WMS形成可查询、可分配、可追溯库存
  -> OMS/ERP/平台产生出库指令
  -> WMS接收出库单、分波、拣货、复核、称重、发运
  -> TMS/LMS尾程配送
  -> OMS/ERP/平台接收WMS状态与库存回写
```

课程里把跨境物流链路拆成“头程 -> 海外仓 -> 尾程”。WMS真正接手的是海外仓这一段，但它不能脱离上下游理解：上游为什么按箱来、为什么有箱唛、为什么要备货；下游为什么要称重、为什么要面单、为什么要回写发货状态。

#### 1.3.2 主干流程一：入库主流程 [地基] [高]

```text
[OMS/ERP/客户系统] 创建入库预报/ASN，维护SKU、箱唛、预计数量、预计到仓信息
  -> [头程/承运方] 将货物送达海外仓，货物按箱/托盘到仓
  -> [收货员] 通过箱唛、入库单号、客户/货主信息识别到仓货物
  -> [收货员] 按箱、SKU、数量进行清点，提交实收结果
  -> [WMS] 生成收货记录，标记已收、部分收货或收货差异
  -> [质检员] 对命中质检规则的商品检查良品、次品、破损、效期
  -> [WMS] 区分良品、次品、待处理/冻结库存
  -> [上架员] 根据上架任务把货从收货暂存区搬到目标库位
  -> [WMS] 记录SKU、批次、库位、数量，形成库位库存和库存流水
  -> [OMS/ERP] 接收WMS收货、上架、库存变化回写
```

这个流程里最关键的业务理解点：

- **ASN不是实收结果**：它是上游提前告诉仓库“会来什么货”的依据。
- **箱唛是到仓识别入口**：尤其海外仓按箱收货，箱唛能降低无主货和错货风险。
- **收货、质检、上架是三个动作**：收货确认“到了多少”，质检确认“好坏状态”，上架确认“放到哪里”。
- **库存增加时机后续在L2展开**：Phase 1只说明业务动作，不展开收货增库存/上架增库存的设计决策。

#### 1.3.3 主干流程二：库存主流程 [地基] [高]

```text
[WMS] 入库上架后形成SKU库存、库位库存、批次库存或库位-批次库存
  -> [库存管理员/仓库主管] 查询总库存、可用库存、锁定库存、冻结库存、库位库存
  -> [OMS/ERP] 查询或接收库存同步，用于订单处理、补货、调拨或销售决策
  -> [WMS] 出库分配时锁定库存，取消时释放库存，发运时扣减库存
  -> [仓库人员] 发生移库、盘点、调整时提交库存变更动作
  -> [WMS] 记录库存流水，保留每一次变化的来源单据、原因和数量
```

库存链路要先理解一个底层事实：仓库现场看到的是实物，系统记录的是数字。WMS要做的事情，就是让系统里的数字能解释实物为什么在这里、为什么可用、为什么被锁、为什么被冻结、为什么被扣掉。

库存业务里有四个常见视角：

| 视角 | 业务含义 | 后续进入 |
|---|---|---|
| SKU库存 | 某个SKU总体有多少 | L2库存汇总模型 |
| 库位库存 | 某个SKU在哪些库位，有多少 | L2库位库存 |
| 批次库存 | 同一SKU不同批次、效期、供应商等差异 | L2批次管理 |
| 库位-批次库存 | 某个库位上某个SKU某个批次有多少 | L2最细粒度库存 |

#### 1.3.4 主干流程三：出库主流程 [地基] [高]

```text
[平台/ERP/OMS] 产生销售订单、调拨出库或备货中转指令
  -> [OMS/ERP] 审核订单、确认仓库、物流、库存和出库要求
  -> [WMS] 接收可执行出库单
  -> [WMS/仓库主管] 按订单类型、承运商、截单时间、SKU结构生成波次
  -> [WMS] 对波次内订单进行库存分配或库位推荐
  -> [拣货员] 按拣货任务到库位拣货，把货放入拣货容器
  -> [分拣员] 对需要二次分拣/播种的波次，将商品匹配到订单格口或容器
  -> [复核员] 按一单一件、一单多件等方式核对SKU、数量、订单/格口/跟踪号
  -> [打包/称重员] 打包、称重，校验物流重量和包裹信息
  -> [WMS] 确认出库/发运，扣减库存并回写出库状态
  -> [TMS/LMS/承运商] 承接尾程配送
```

出库链路里最重要的业务理解点：

- **一件代发本质是B2C出库**：小件、多单、SKU数量少，适合批量分波和播种。
- **备货中转本质是B2B出库**：数量多、箱/托盘维度更强，往往不适合完全套B2C播种逻辑。
- **波次是为了集中处理订单**：课程13用“帮室友去超市买东西”解释波次，本质是把多笔订单共同需要的货汇总一次性拣。
- **复核是发错货前的最后防线**：课程15用手机128G拣成256G/512G的例子说明，复核不是形式动作，而是拦截错发漏发。

### 1.4 分支流程

#### 1.4.1 入库分支流程 [地基] [高]

节点【入库类型】出现分支：

```text
├── 备货入库
│   -> 国内先装箱、贴箱唛、打托
│   -> 海外仓按ASN和箱唛收货
│   -> 适合作为WMS入库主线
├── 调拨入库
│   -> 同国家/跨区域仓之间调拨，例如美东仓调到美西仓
│   -> 业务模式类似备货入库，但来源仓和目的仓都要关注库存变化
├── 采购入库
│   -> 国内仓/ERP常见，海外仓场景不是最高频
│   -> 可作为上游ERP来源背景保留
└── 退货/RMA入库
    -> 消费者退货、派送失败退回、FBA移除、第三方仓拒收等
    -> 进入逆向流程，不作为入库主线
```

节点【收货结果】出现分支：

```text
├── 数量一致
│   -> 生成正常收货记录
│   -> 进入质检或待上架
├── 少收
│   -> 记录实收小于预报数量
│   -> 回写上游差异，等待补货或关闭差异
├── 超收
│   -> 标记实收大于预报数量
│   -> 需要确认是否接收、补录或退回
├── 货不对板
│   -> SKU/箱唛/规格与ASN不一致
│   -> 暂停入库，进入异常处理
└── 无主货
    -> 箱唛缺失或无法匹配入库单
    -> 放入异常区，等待人工认领或补单
```

节点【质检】出现分支：

```text
├── 不需要质检
│   -> 直接进入待上架
├── 质检合格
│   -> 良品进入可上架范围
├── 质检不合格
│   -> 次品/破损/过期/效期不足进入不合格区或冻结/待处理
└── 部分合格
    -> 良品和次品拆分处理，分别进入不同库存状态或库位
```

#### 1.4.2 库存分支流程 [进阶] [高]

节点【库存变动】出现分支：

```text
├── 入库上架
│   -> 增加库存，记录来源入库单/上架单
├── 出库分配
│   -> 锁定库存，可用库存减少，锁定库存增加
├── 订单取消
│   -> 释放锁定库存，可用库存恢复
├── 发运出库
│   -> 扣减实际库存和锁定库存
├── 移库
│   -> 源库位减少，目标库位增加，总库存不变
├── 盘点
│   -> 实物与系统比对，产生盘盈/盘亏差异
└── 库存调整
    -> 经确认后调整库存，必须记录原因和流水
```

节点【库存查询维度】出现分支：

```text
├── 按SKU查询
│   -> 看某个SKU总体库存
├── 按库位查询
│   -> 看某个库位放了什么货
├── 按批次查询
│   -> 看同SKU不同批次/效期库存
└── 按库位-批次查询
    -> 看最细粒度的实物位置和批次数量
```

#### 1.4.3 出库分支流程 [地基] [高]

节点【出库业务类型】出现分支：

```text
├── B2C一件代发
│   -> 小件、多单、单量高
│   -> 适合按波次、播种、复核、称重、发运处理
├── B2B备货中转
│   -> 大件、整箱、托盘或批量出库
│   -> 更关注箱/托盘、装车、交接和目的仓要求
├── FBA退货换标后再发
│   -> 需要换标、加工、重新上架或再出库
└── 拆柜转运/Cross Docking
    -> 到仓后不长期存储，直接拆分转运
```

节点【波次生成】出现分支：

```text
├── 单品单件波次
│   -> SKU结构简单，复核可更快
├── 单品多件波次
│   -> 同一SKU多件，需要核数量
├── 多品混合波次
│   -> SKU多、订单结构复杂，更依赖二次分拣和复核
├── 按承运商/物流渠道组波
│   -> 便于后续面单、集货、交接
└── 按截单时间/优先级组波
    -> 保证SLA和紧急订单履约
```

节点【拣货方式】出现分支：

```text
├── 摘果式拣货
│   -> 按订单逐单拣，简单直观，适合低单量或SKU分散
├── 播种式拣货
│   -> 多单合并拣货，再按订单格口分播，适合B2C小件高单量
└── 先拣后分/边拣边分
    -> 取决于现场设备、容器、播种墙和订单结构
```

节点【复核方式】出现分支：

```text
├── 一单一件复核
│   -> 可按波次号或批量方式快速校验
├── 一单多件复核
│   -> 通常扫出库单、物流跟踪号或格口号，逐单匹配实物
└── 复核异常
    -> SKU、数量、重量、批次不一致时拦截，不允许直接发运
```

### 1.5 逆向流程

#### 1.5.1 出库取消/撤销流程 [地基] [高]

```text
[OMS/ERP/平台运营] 发起取消或截单请求
  -> [WMS] 判断出库单当前作业阶段
  -> 如果未分配库存：直接取消，不影响库存
  -> 如果已分配未拣货：释放锁定库存，记录释放流水
  -> 如果已拣货未发运：仓库确认实物位置，必要时生成回库/复位动作
  -> 如果已复核/已称重未交接：判断是否可拦截，取消包裹或重置作业状态
  -> 如果已发运：不可直接取消，进入物流拦截或退货/RMA流程
  -> [WMS] 回写取消结果、失败原因或拦截状态给上游
```

业务理解要点：

- 取消不是一个简单按钮，要看货到了哪个作业阶段。
- 已经发运的订单不能直接把库存加回去，只能走物流拦截、退货或逆向入库。
- 取消会影响锁定库存、拣货容器、复核状态、包裹状态和上游订单状态。

#### 1.5.2 退货/RMA入库流程 [加分] [中]

课程18补充了海外仓退货来源：消费者退货、物流派送失败退回、FBA移除、FBA仓或第三方仓拒收。Phase 1先按业务链路理解：

```text
[消费者/平台/FBA/承运商] 产生退货或退件
  -> [OMS/ERP/运营] 创建退货/RMA或退件入库指令
  -> [WMS] 接收退件入库单
  -> [收货员] 按包裹、SKU、数量识别退回货物
  -> [质检员] 判断可二次销售、需换标、需维修、需报废、需退供
  -> [WMS] 根据质检结果进入良品上架、次品区、待处理区或报废流程
  -> [WMS] 回写退货处理结果和库存变化
```

#### 1.5.3 库存盘点/调整逆向纠偏流程 [进阶] [高]

```text
[库存管理员] 发现账实不一致或发起周期盘点
  -> [WMS] 创建盘点单或盘点任务
  -> [盘点人员] 对指定库区/库位/SKU进行清点
  -> [WMS] 对比系统数量和实物数量
  -> 如果一致：盘点完成
  -> 如果盘盈/盘亏：生成差异
  -> [仓库主管/库存管理员] 复核差异原因
  -> [WMS] 审批后执行库存调整，生成库存调整流水
```

业务理解要点：

- 盘点不是异常本身，而是发现和纠正库存差异的机制。
- 盘点差异不能随便改库存，要有原因、审批、流水。

### 1.6 异常流程入口

Phase 1只列异常入口，不展开完整处理方案；完整异常兜底放到Phase 2。

| 异常类别 | 发生环节 | 触发条件 | L2需要展开 |
|---|---|---|---|
| 到仓识别异常 | 入库收货 | 箱唛缺失、箱唛无法匹配ASN、货主/客户不清楚 | 无主货、错货、人工认领、补单 |
| 收货差异 | 入库收货 | 实收数量大于/小于预报数量，或SKU/规格不一致 | 超收、少收、货不对板 |
| 质检异常 | 入库质检 | 破损、次品、过期、效期不足、批次属性异常 | 冻结、退供、报废、让步接收 |
| 上架异常 | 入库上架 | 库位不可用、库位超容、批次/混放限制不满足 | 人工指定库位、异常区、库位调整 |
| 库存账实异常 | 库存管理 | 系统数量和实物不一致，拣货缺货或盘点发现差异 | 盘点、调整、冻结、责任原因 |
| 锁定释放异常 | 出库/取消 | 订单取消后锁定库存未释放，或释放失败 | 释放队列、补偿、对账 |
| 波次生成异常 | 出库波次 | 订单不满足规则、库存不足、规则配置冲突 | 手动建波、规则调整 |
| 拣货缺货 | 出库拣货 | 分配成功后到库位无货、少货、批次不符 | 二次分配、补拣、订单拦截 |
| 复核异常 | 出库复核 | SKU、数量、订单、格口、重量不一致 | 拆包复查、退回重拣 |
| 称重/面单异常 | 出库发运 | 重量超差、承运商限制、面单失败 | 重称、换承运商、重试 |
| 上下游同步异常 | 接口协同 | WMS接单失败、状态回写失败、库存同步延迟 | 幂等、重试、日志、人工补推 |

### 1.9 Cross Docking 与普通转运

课程中直接讲到拆柜转运、备货中转和海外仓存储场景。按L1模板补齐业务理解：

| 类型 | 业务含义 | WMS关注点 | 适用场景 |
|---|---|---|---|
| 普通转运/备货存储 | 货到海外仓后先入库、上架、存储，后续按订单出库 | 入库、库位、库存、波次、拣货、复核全链路 | 预测备货、长期海外仓销售 |
| Cross Docking/交叉转运 | 货到仓后不长期存储，直接拆分、分拨、转运出去 | 到仓识别、分拣、暂存、交接、状态回写 | 拆柜转运、快速中转、FBA补仓 |

Phase 1只做业务区分；具体要不要独立模块、是否影响库存、是否需要暂存库位，放到Phase 2设计。
